# Creative Showcase

## Project Overview
A lightweight React application demonstrating clean fundamentals, routing, mock authentication, and a CSS-based masonry image gallery. All data is persisted in **localStorage**, making it a pure frontend product without any backend.

## Tech Stack
- **React** (with Vite) 
- **JavaScript**
- **HTML / CSS**
- **react‑router‑dom** for client‑side routing
- **localStorage** for mock authentication and image storage

## App Routes
| Route | Description |
|------|-------------|
| `/` | Landing page – shows a random selection of images from all users in a masonry layout. |
| `/signup` | Sign‑up form (username, email, password). Stores credentials in localStorage. |
| `/login` | Login form – validates against stored credentials. |
| `/dashboard` | Private user dashboard (protected). Allows image upload, preview, and displays the user's gallery. |
| `/profile/:username` | Public profile page – displays the selected user's images. |

All routes work on page refresh when deployed.

## Authentication (Mocked)
- **Signup** stores `{ username, email, password, images: [] }` under a top‑level `users` object in localStorage.
- **Login** validates the entered credentials against the stored user data.
- On successful login, a `currentUser` object is saved in localStorage.
- **Protected routes** (`/dashboard`) use a `PrivateRoute` component that redirects unauthenticated users to `/login`.
- **Logout** clears `currentUser`.

> **Security disclaimer:** This is a demonstration only. Storing passwords in plain text in localStorage is insecure and must not be used in production.

## Image Storage Approach
- Images are uploaded via `<input type="file" />`.
- A preview is shown using a **Base64** data URL generated by `FileReader`.
- The Base64 string is stored in the user's `images` array in localStorage.
- Images persist across page refreshes and are isolated per user.

## Masonry Layout
A pure‑CSS masonry layout is implemented using **CSS columns** (`column-count`). This approach avoids heavy third‑party libraries, keeping the bundle size small and ensuring good performance.

```css
.masonry-grid {
  column-count: 3;
  column-gap: 1rem;
}
```

## Limitations
- No real backend – data is stored locally and is cleared when the browser storage is cleared.
- Passwords are stored in plain text (acceptable only for this mock demo).
- Images are stored as Base64 strings, which can increase localStorage usage.

Note: localStorage size is limited (typically ~5MB per origin in many browsers). Storing Base64 images can quickly exhaust available space; this demo documents that limitation and is intended only for small uploads or toy data.

## Future Improvements
These improvements are intentionally out of scope for this frontend-only assignment:

- Replace localStorage with a real backend (e.g., Node/Express, database).
- Use secure password hashing and authentication tokens.
- Implement cloud storage for images (e.g., AWS S3, Cloudinary).
- Add pagination or infinite scroll for large image collections.
- Enhance UI/UX with a design system or component library.

## Deployment
The app is currently deployed to **Vercel** (or any static hosting) with a single command:

```bash
npm run build
# The `dist` folder can be uploaded to Vercel
```

Vercel automatically serves the `dist` directory and supports client-side routing. Ensure the `vercel.json` (if used) includes a rewrite rule for SPA fallback.
